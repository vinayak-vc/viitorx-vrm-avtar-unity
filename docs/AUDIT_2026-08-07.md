## 0. Root cause — why bugs keep recurring

The system was rebuilt across many sessions (BlazePose→Sentis RTMW3D→OAK-D UDP sidecar) and the same
responsibility now lives in **two places at once**, with each session fixing one layer and leaving the
other. Every recurring symptom traces back to this split:

1. **Mirror is applied in BOTH the sidecar (`--mirror`) and Unity (`PoseSpaceConverter.poseFlipX`)** — only a code comment keeps them from double-flipping.
2. **Smoothing runs in BOTH the sidecar (`smoothing.py`) and Unity (`JointFilterPipeline`)** — two cascaded One-Euro stages → lag.
3. **Torso uprightness is fought over by three mechanisms**: sidecar `--flatten-trunk` (zeros shoulder/hip Z), retarget `StableUp` (zeros hip-line Y), and the front-facing calibration gate — and the trunk-flatten silently **breaks** the other two.
4. **Config lives in two places**: `AppSettings`/`settings.json` (written, never read) vs `[SerializeField]` Inspector fields (the real source) — they disagree.
5. **Three body backends + a dead IK path** all remain wired simultaneously; precedence hides which is live.

**The single highest-value action is to make each transform (mirror, smoothing, uprightness, config) have exactly ONE owner and delete the duplicate.**

## 2. HIGH severity

- **H1 — HUD perf monitor never instantiated.** `AppBootstrap.cs:97` declares `performanceMonitor`; it is never `new`'d, so `DiagnosticsHudPanel.Initialize(null)` leaves the FPS/frame-time HUD permanently blank (`DiagnosticsHudPanel.cs:37` guard never true). Fix: `performanceMonitor = new PerformanceMonitor();` in `InitializeServices`.
- **H2 — `AppSettings` schema written but never read back.** Only `Avatar.LastPath` is consumed; Camera/Tracking/Smoothing/Ik/Display sections are inert, and defaults diverge (`CameraSettings.Fps=60` vs serialized `cameraFps=30` vs HUD string "30fps"). Calibration changes never persist. Fix: one source of truth — bind serialized fields from `settingsStore.Current` at init + persist on change, or delete the unused schema.
- **H3 — Face/hand retargeters don't rebind on avatar hot-swap.** `AppBootstrap.cs:250,265` bind expression/hand retargeters only `if (!IsBound)`; after an avatar swap they still target the disposed rig (body rebinds correctly via `animator != boundAnimator`). Fix: reset/rebind expression + hand retargeters in the animator-changed block.
- **H4 — MediaPipe pose provider Glog refcount leak on start failure.** `MediaPipePoseProvider.cs:91` calls `MediaPipeGlobalInit.Acquire` but the catch (`:112`) never `Release`s (Face/Hand providers do). Repeated start failures inflate the refcount so `Glog.Shutdown` never runs. Fix: add `MediaPipeGlobalInit.Release(logService);` to the catch.
- **H5 — Runtime IK toggle is dead; whole IK driver unreachable in shipping config.** `ikSolver` is constructed only at startup and only if `useIkDriver` was already true (`AppBootstrap.cs:334`); scene ships `useIkDriver:0`, and the toggle only flips the bool (`:512`), so `ikActive` (`:220`) is forever false. All of `AnimationRiggingIkDriver` is dead code as shipped. Fix: lazily construct+Bind on toggle-on, or annotate the toggle.
- **H6 — Leg plausibility gate only in the dead IK path; FK legs ungated.** The ankle-drop check that prevents hallucinated occluded legs lives at `AnimationRiggingIkDriver.cs:305` (dead). FK `ApplySegments` has no equivalent, and the scene ships `trackLegs:1` — the exact config the code comment (`AppBootstrap.cs:55`) warns causes folded/splayed legs. Fix: move the ankle-drop gate into the shared FK leg path; reconcile `trackLegs` default.
- **H7 — Sidecar `build_hand` ignores confidence → hands always emitted as tracked.** `wholebody_udp_sender.py:90-105` never reads `conf`/`conf_thr`; body respects the threshold but hands don't, so `OakDUdpPoseProvider` always reports hands tracked and curls fingers from noise when hands aren't visible. Fix: gate each hand on wrist/quorum confidence; mark untracked so Unity `ReadHand` returns null.

## 3. MEDIUM severity

- **M1 — IK/Face/Hand toggles no-op when the feature started disabled.** Providers/solver are constructed once behind the same bool (`AppBootstrap.cs:334,377,396`); toggling on later does nothing (stays null). Fix: lazy-construct on enable, or always construct and gate on the bool.
- **M2 — Mirror applied in two layers.** Sidecar `--mirror` (negate X + swap L/R) and Unity `PoseSpaceConverter.signX` via `poseFlipX` (`AppBootstrap.cs:509`) both flip X; enabling both cancels. Only a comment coordinates them. Fix: single-source it — hard-gate `poseFlipX` off when OAK is active (or drive it from the sidecar), documented in one place.
- **M3 — Double smoothing on the OAK path.** Sidecar One-Euro (`wholebody_udp_sender.py:171`) then Unity `jointFilter.Filter` (`AppBootstrap.cs:216`) — two cascaded low-pass stages → the "under-responsive" feel. Fix: own smoothing in one place; bypass/loosen the other for OAK.
- **M4 — Session/`AvatarChanged` leak on scene reload.** `SetupAvatarSession` (`AppBootstrap.cs:443`) rebuilds `avatarSession` and re-subscribes without disposing the prior one. Fix: unsubscribe + `Dispose()` the old session first.
- **M5 — No `OnDestroy`/domain-reload teardown → UDP port/thread leak.** Provider disposal is only in `OnApplicationQuit`; a script recompile while playing leaks the OAK socket+thread → next run hits "port 8899 in use" and silently falls back. Fix: shared `TeardownServices()` called from `OnApplicationQuit` and `OnDestroy` (guard double-dispose).
- **M6 — Trunk-flatten defeats the front-facing calibration gate + degrades body-forward.** `HumanoidPoseRetargeter.cs:198` derives front-facing from `abs(shoulderLine.x) >= abs(shoulderLine.z)`; the sidecar zeros shoulder/hip Z, so this is **always true** (the "don't lock a bad neutral while turned" guard never fires), and `ComputeBodyForward` (`:281`) loses its Z facing signal → weaker roll reference for every limb → twist. Fix: derive facing from a depth-independent signal, or stop depth-flattening upstream if this gate must work.
- **M7 — `WebcamCaptureService.StartCapture` always returns true.** `:85` — `WebCamTexture.Play()` doesn't guarantee the device opened; failures are reported as success → silent black texture. Fix: verify `isPlaying`/non-zero size next frame and return the real state.
- **M8 — Avatar hot-swap async race.** `AvatarSessionController.cs:74` doesn't re-check the cancellation token after `await`; an older overlapping load can dispose the newer `current` and install the wrong avatar (+leak). Fix: bail if `token.IsCancellationRequested` after the await, disposing the stale instance.
- **M9 — OAK receive-thread double-buffer race.** `OakDUdpPoseProvider.cs:120` writes `workerFrame`/`workerHandFrame` outside `gate` while the consumer swaps them under lock — torn-data risk (the one provider that differs from the MediaPipe pattern). Fix: capture the write-target under `lock(gate)` per iteration, or make the buffer fields volatile.
- **M10 — One-Euro dt is the render delta, not the inter-sample delta.** `AppBootstrap.cs:216` passes `Time.deltaTime`; `TryGetLatestFrame` returns the same cached frame every Update, so the filter re-runs ~60 Hz over ~30 Hz data → derivative divided by ~16 ms not ~33 ms → mistuned beta. Fix: filter only on genuinely-new frames using `frame.TimestampSeconds` deltas; give OAK/Sentis real arrival timestamps.
- **M11 — Whole-frame stall when one hip lacks depth.** `wholebody_udp_sender.py:184` requires BOTH hips measured or the frame is skipped, dropping a good upper body. Fix: fall back to one hip or hold the last good mid-hip for a few frames.
- **M12 — Finger-curl mapping is positionally fragile.** `HumanoidHandRetargeter.cs:157` maps a fixed 15-slot curl array onto a list that skips absent bones (`:149`); a missing intermediate bone shifts every later finger's curl. Fix: store finger identity/curl on each `FingerJointPair` at bind.
- **M13 — `RotationFromVectors` roll reference can differ between rest and target.** `RotationFromVectors.cs:17` — `SafeUp` may pick different fallbacks for rest vs target directions → spurious twist. Fix: resolve one consistent up and use it for both bases.
- **M14 — `ApplyWrist` not inert on the MediaPipe fallback + ungated neutral.** OAK sets wrist untracked, but if OAK fails and MediaPipe hand takes over it sets `tracked=true` (`MediaPipeHandProvider.cs:289`) with `wristWeight=0.7`, capturing neutral on the first frame with no front-facing gate → bad neutral until `C`. Fix: stop setting tracked=true (or force weight 0), or gate neutral like the torso.
- **M15 — Person-box tracker can wedge.** `wholebody_udp_sender.py:163` only re-acquires (center reset) when <4 keypoints pass; if RTMW3D hallucinates ≥4 in a bad box, 0.7 inertia keeps it there with no recovery. Fix: reset on sustained low measured-count/confidence, or periodic full-frame re-detect.
- **M16 — Dead RTMW3D `zrel` decode.** `wholebody_udp_sender.py:161` decodes monocular z every frame and discards it; depth holes fall to a flat hip-plane instead of the model's root-relative z. Fix: use `zrel` (scaled to hip depth) as the hole fallback, or drop the z head.
- **M17 — Stale docstring / two senders.** `OakDUdpPoseProvider.cs:17,206` still name `depthai_blazepose/udp_pose_sender.py` and a body-only contract; the canonical sender is `wholebody_udp_sender.py` (with `lh/rh/src`). With the old sender, hands silently never track. Fix: fix the docstring; warn once when datagrams arrive without `lh`/`rh`; label the BlazePose sender deprecated.
- **M18 — OAK path uses calm-webcam filter defaults.** Only Sentis retunes `jointFilter`; OAK keeps `minCutoff=1/beta=0.2` on a noisy stream. Fix: OAK-specific params (or fold into the single-owner smoothing decision, M3).

## 5. Consolidation / refactor opportunities

1. **One transform owner** (the root-cause fix): mirror, smoothing, uprightness/trunk, and config each in exactly one layer; delete the duplicates and their dead flags.
2. **`MediaPipeVideoProviderBase`** — pose/face/hand providers copy-paste the worker/pool/double-buffer scaffold verbatim (would have prevented H4).
3. **`HandLandmarkDecoder`** — finger-joint constants + `FingerCurl` + `PalmRotation` are duplicated verbatim in `MediaPipeHandProvider` and `OakDUdpPoseProvider`.
4. **`DoubleBuffer<T>`** — the worker/main swap appears in all 5 providers; unify (fixes M9 in one place).
5. **Shared limb/torso math** — `TorsoUp`/`BodyForward`/leg-classification are duplicated across `HumanoidPoseRetargeter` and `AnimationRiggingIkDriver`; and a `NeutralTracker` (capture+delta+reset) would unify torso + wrist and give the wrist the torso's gating (fixes M14).
6. **`pixel_to_cam` helper** + a single "emit-if-confident else fallback" routine in the sidecar (fixes H7's inconsistency); shared monotonic timestamp helper.
7. **Single generic `FindInScene<T>(scene)`** — replaces ~6 copies of the scene-scan loop in `AppBootstrap`.
8. **Single backend enum** instead of three simultaneous `use*Tracking` bools.

## 6. Recommended fix order

1. **Decide the single owner for mirror + smoothing + uprightness (M2, M3, M6)** — this alone removes most recurring symptoms. Recommendation: keep them in the **sidecar**, and make Unity a pass-through (poseFlipX off + loosen/bypass `jointFilter`) OR vice-versa — but pick one.
2. **H7 + M12** (hand confidence gate + robust curl mapping) — fixes finger twitching.
3. **H6** (leg plausibility gate into the FK path) — fixes leg folding.
4. **H3 + M4 + M8** (avatar-swap rebind + session leak + load race) — stability of hot-swap.
5. **H1, H2** (perf HUD + config single-source) — diagnostics + persistence.
6. **H4, M5, M9, M10** (leaks, teardown, race, filter dt) — correctness hardening.
7. LOW batch as cleanup, guided by the consolidation refactors (which prevent recurrence).
