# P1-4 CLOSEOUT — 2026-09-08

## P1-4 = REJECTED

P1-4 (skeleton constraints + long-horizon kinematic recovery) is **rejected for production on the
current pipeline**. It is disabled by default, retained on disk for forensic reference only, and must
not be re-enabled without first solving the upstream measurement-quality problem described in §5.

This supersedes the earlier "COMPLETE (conditional)" status and ADR-P008's "READY WITH CONDITIONS".
That verdict was reached from **offline replay**. Live hardware validation with a human subject
contradicted it.

Production path is now, and must remain:

```text
P1-1 → P1-2 → UDP → P1-3 → Kalidokit → P0 LimbGate → VRM
```

and **not**:

```text
P1-1 → P1-4 → UDP → ...
```

---

## 1. Why P1-4 failed

### 1.1 It missed the corruption it exists to catch

Block 8 of the live protocol injects a known 0.85 m right-knee fault upstream of P1-1 and P1-4 at
high confidence (`--inject-drift-file`, TEST-ONLY). This is the **only fully controlled comparison in
the run** — synthetic, identical stimulus in both passes.

| pass | injected | error reaching the wire | `GEOMETRIC_REJECT` | `RECONSTRUCT` |
|---|---|---|---|---|
| P1-3 baseline — drift | 0.85 m | 0.8388 m | 0 | 0 |
| P1-3 baseline — teleport | 0.85 m | 0.8542 m | 0 | 0 |
| **P1-4 — drift** | 0.85 m | **0.8419 m** | **0** | **0** |
| **P1-4 — teleport** | 0.85 m | **0.8439 m** | **0** | **0** |

P1-4 did not fire at all, and delivered no measurable benefit over the baseline.

### 1.2 The rejection signal overlaps its own noise floor

An 0.85 m lateral knee displacement produces a femur `relLenErr` of only **≈ 1.50**. The shipping
`seg_reject` threshold is **1.80**, chosen (ADR-P008) because *clean* human capture already reaches
**p99 = 1.791** of relative bone-length deviation.

```text
corruption we must detect   ≈ 1.50
natural variation p99       ≈ 1.79   <-- larger than the signal
rejection threshold           1.80
```

**The signal sits below the noise. The safe threshold band is empty.** Lowering the threshold to catch
1.50 reproduces the previously measured 25.3% false-positive collapse; raising it disables P1-4. No
constant works, which is why this is a closeout and not another tuning round.

A secondary mechanism compounds it: P0-2's 0.35 m/frame leg cap slews a teleport across several
frames, so the bone-length estimator's rolling median **learns the corrupted length** instead of
rejecting it.

### 1.3 87% of its rejections came from that unreliable signal

Over the run: **1129 `GEOMETRIC_REJECT`**, split `segment: 1001` / `angle: 128`. Observed rejections
fired at `relLenErr` 1.817 against a 1.80 threshold — i.e. **at the noise floor**. The scale-free angle
check remains the only trustworthy part.

### 1.4 It degraded the avatar

| metric | P1-3 | P1-4 |
|---|---|---|
| rendered frames with a limb **HELD** by the P0 gate | **0.47%** | **17.83%** |
| LOST episodes | **1** | **122** (4.65% of run, longest 0.607 s) |
| avatar snaps > 45° per pose | **15** | **27** |
| `kneeAng.l` minimum | 75.0° | **12.5°** |

Within-pass control (event-adjacent frames vs everything else, *same* performance, so free of the
"danced harder" confound):

| | rotation p99 | rate > 20°/frame |
|---|---|---|
| within 250 ms after a P1-4 event | **22.08°** | **1.248%** |
| no event | 4.51° | 0.095% |

**13× more likely to snap.** Of 67 snaps > 20°, **30 are attributable to P1-4 stages** (21
`GEOMETRIC_REJECT`, 5 `RECOVERING`, 4 `RECONSTRUCT`). Per event kind, `RECOVERING` had a *median*
avatar response of 15.16° and `WEAK→LOST` 19.26°.

### 1.5 Reconstruction moved joints by metres

From P1-4's own telemetry. `recon_err` is **displacement from the rejected measurement**, not error
against ground truth — but no valid human knee is metres from its own measurement in a room where the
subject stands ~2 m from the camera:

| joint | mean displacement | max |
|---|---|---|
| right_knee | 0.88 m | 2.20 m |
| left_knee | **2.19 m** | **4.16 m** |

### 1.6 Cost was acceptable — correctness was not

CPU (0.329 vs 0.173 ms p50) and latency (42.2 vs 39.1 ms p50) were both well within budget.
**P1-4 was not rejected for performance. It was rejected for correctness.**

### Correction to the prior P1-4 report

Two claims in the pre-closeout report did not survive hardware validation:

1. "Reconstruction is dormant on live data" — **wrong**; it fired 41 times.
2. "−68% improvement on slow impossible knee drift" — **did not reproduce**; the offline replay's
   synthetic geometry happened to exceed 1.80, live geometry does not.

## 3. Rollback verification (live, human in frame)

Same 9 blocks, shipping default, **no recovery flag passed** (`blocks.json` records `recovery: ""`).

**P1-4 is completely inert:** 0 `GEOMETRIC_REJECT`, 0 `RECONSTRUCT`, 0 `RECOVERING`, 0 events tagged
`stage=P1-4`, out of 9921 tracker events.

Blocks 1–8 (block 9 excluded — see the note below), measured **per pose**, which is render-rate
independent:

| metric | P1-3 baseline | P1-4 | **rollback** |
|---|---|---|---|
| P0 limb-held | 0.28% | 15.84% | **0.14%** ✅ |
| LOST episodes | 1 | 111 | **1** ✅ |
| snaps > 45°/pose | 12 | 20 | **13** ✅ |
| rotation p99 | 35.61° | 34.92° | **34.27°** ✅ |
| rotation p95 | 12.95° | 13.81° | 16.32° (see below) |
| tracker CPU p50 / p99 | 0.173 / 0.284 ms | 0.329 / 0.550 ms | **0.175 / 0.310 ms** ✅ |
| latency p50 / p95 | 39.1 / 44.5 ms | 42.2 / 47.8 ms | **40.8 / 44.0 ms** ✅ |
| packet loss | 0 (4717/4717) | 0 (4856/4856) | **0 (4859/4859)** ✅ |
| bone-length CV (all 4 bones) | 0.00000 | 0.00000 | **0.00000** ✅ |

**Baseline restored.** Every P1-4-attributable regression is gone; CPU is back to P1-1-only cost.

Two residuals, both stimulus rather than regression — stated rather than hidden:

- **p95 16.32° vs 12.95°.** The rollback run contained **1.48× more input motion** than the baseline
  (0.01270 vs 0.00852 m/frame mean wrist+knee displacement). Despite 48% more motion, the tail
  metrics (p99, snaps > 45°, gate-held, LOST) are at or better than baseline.
- **Block 9 excluded.** In the rollback run the operator achieved *genuine* total occlusion — 116
  frames below 0.5 coverage vs **0** in the baseline run. Its 151 LOST events are P1-1 and the P0
  LimbGate responding correctly to a subject who actually left the frame, not a regression. The
  baseline run never reached that state, so the two block 9s are not comparable.

## 5. Architectural conclusion — record this

> **Skeleton-level kinematic reconstruction cannot currently be made reliable using the present
> landmark geometry, because the bone-length signal's natural variation overlaps the corruption
> signal we need to detect.**

Therefore:

```text
DO NOT continue threshold tuning.
DO NOT add more smoothing.
DO NOT add more heuristic rejection layers on the same unstable signal.
```

The next investigation must target the **upstream measurement-quality problem**, not another
downstream heuristic.

---

## 6. Next phase — audit only, no implementation

Evidence-first investigation of **F-08 / confidence normalization** and **upstream landmark/depth
metric stability**. Determine specifically why:

- high-confidence wrong joints keep their high confidence;
- bone lengths fluctuate so strongly frame to frame;
- depth/landmark geometry can become physically impossible while confidence stays high.

Then determine which of these is the useful next step:

```text
better confidence calibration
better RGB/depth temporal correspondence
better depth sampling
joint-specific measurement quality
another upstream signal entirely
```

**Produce the audit first. Do not implement any of them yet.**
